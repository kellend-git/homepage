Postman Fabric Gateway / Overview

Lightyear cuts the cost of agent loops.

Lightyear runs between a coding agent and its model provider. It handles deterministic steps in Fabric Gateway, so the model makes fewer inference passes and the agent keeps its existing tools and permissions.

How it fits into the request path

  1. Coding agent

    The client sends requests through Fabric and runs tools under its existing permissions.

  2. Fabric Gateway

    Lightyear handles deterministic orchestration and reduces repeated context on the route.

  3. Model provider

    The existing model handles the steps that require reasoning.

Platform teams can enable Lightyear on an LLM Router route and point agents at that route. Fabric analytics estimates savings against direct provider usage at list prices. Routing and analytics docs

Technical details

Where the inference savings come from

In a conventional loop, a tool result can trigger another model request carrying the conversation so far. Lightyear’s code mode handles deterministic orchestration inside Fabric, and its cache optimizations reduce repeated context. The client still executes tools and enforces its permissions.

Fewer model passes

Routine steps between model decisions can run in the gateway, reducing calls back to the model.

Less repeated context

The gateway can compact and restructure requests before passing them to the provider.

Existing permissions

Reads, edits, and other tool actions still execute on the client under its configured controls.

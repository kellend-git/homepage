Postman · API migration

Catching silent regressions in API migrations

In this example, the migration changed a fee by one cent. Both versions of the API calculate the same $20.645 fee before rounding. The legacy service rounds a tie to the even cent. The replacement rounds it up. Both return a valid number, so the response schema accepts either result.

Record before you rewrite

Postman Bootstrap turns legacy responses into a repeatable release check for continuous integration (CI).

  1. 1. Plan and review

    Review the OpenAPI description and choose cases for boundary values, defaults, and error paths.

  2. 2. Capture and self-test

    Record the original before it changes. Replay the cases against it to verify the baseline.

  3. 3. Migrate and verify

    Point the same check at the replacement and report differences in CI.

The legacy interface determines what you can verify

Live comparison
Record responses from a running service and test the replacement with the same requests.
Snapshot replay
Capture original inputs and outputs for replay, for example through a batch or library adapter.
Contract only
Check conformance and report regression as skipped when original behavior cannot be replayed.

Postman Bootstrap · Technical details

Keep the baseline independent of the rewrite

A person reviews the capture plan before recording. An agent can propose cases, and the generated gate runs repeatable checks using the recorded evidence. Changes to expected behavior are reviewable in the repository.

Eight checks in the release gate

governance
governance-workspace
Lint the OpenAPI file with Spectral. When a workspace is configured, apply its Postman rules too.
contract
contract-live
Check expected responses against the mock and the running target, when each is configured.
oracle-integrity
corpus-spec
Check the baseline fingerprint and verify that recorded responses agree with the spec.
corpus-selftest
regression
Verify the recording against the original in a self-test, then compare the replacement with the same capture.

Comparisons start exact. Any field excluded from comparison, such as a generated timestamp, is recorded in the manifest.

What the verdict means

PASSED
All in-scope checks passed.
INCOMPLETE
A check still needs input or evidence.
FAILED
A check ran and failed.

The spec, recordings, collections, and environment files live in postman/. The generated ci/gate.sh runs with the Postman CLI and Spectral.
